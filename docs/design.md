# Birth Prep Board — Design Reference

Свіжий погляд на те, що вже задано в `src/app/globals.css` і
`src/components/ui/*`, названий і оформлений як довідник. Наступні
екрани посилаються на цей документ замість дублювання Tailwind-класів
"на око".

## Типографіка

Базовий розмір тексту в системі — `text-sm` (14px), не `text-base` —
так вже побудовані `Card`, `CardDescription` й інші ui-компоненти.
Використовуйте цю шкалу:

| Клас | Призначення | Приклад |
|---|---|---|
| `text-3xl font-heading font-semibold` | Заголовок сторінки (H1) | "Дашборд", заголовок розділу |
| `text-base font-heading font-medium` | Заголовок картки/секції | `CardTitle`-подібні елементи |
| `text-sm` | Базовий текст, весь основний контент | назви пунктів чеклиста |
| `text-sm text-muted-foreground` | Другорядний/описовий текст | `CardDescription` |
| `text-xs text-muted-foreground` | Мета-інформація, підписи | таймстемпи, лічильники |

`font-heading` зараз дорівнює `font-sans` (Figtree) — той самий шрифт,
різниться лише вага/розмір, не гарнітура (`globals.css:12`).

## Spacing

Компоненти в цьому проєкті не хардкодять `p-4`/`gap-6` напряму —
вони визначають CSS-змінну на рівні кореневого елемента і посилаються
на неї через `--spacing()`, як `Card` це вже робить (Tailwind v4 bracket syntax, `card.tsx:15`):

```
[--card-spacing:--spacing(6)]      /* --size=default */
[--card-spacing:--spacing(4)]      /* --size=sm */
```

Для нових складених компонентів (список пунктів чеклиста, рядок
навігації) використовуйте той самий патерн: одна CSS-змінна на
контейнері, а не розкидані утиліти на кожному нащадку — так розмір
компонента можна змінити в одному місці (`data-size` атрибут).

## Радіуси

`--radius: 1rem` — базове значення, з якого виведена вся шкала
(`globals.css:44-50`):

| Токен | Значення | Де вже використовується |
|---|---|---|
| `rounded-sm` (`--radius-sm`) | 0.6rem | дрібні елементи (чекбокси) |
| `rounded-md` (`--radius-md`) | 0.8rem | інпути, badge |
| `rounded-lg` (`--radius-lg`) | 1rem | базові контейнери |
| `rounded-xl` (`--radius-xl`) | 1.4rem | — |
| `rounded-2xl` (`--radius-2xl`) | 1.8rem | `Card` (`card.tsx:15`) |
| `rounded-3xl` (`--radius-3xl`) | 2.2rem | — |
| `rounded-4xl` (`--radius-4xl`) | 2.6rem | `Button`, `Progress`-track (pill-форма) |

## Кольори — семантика

Токени вже визначені для обох тем (`globals.css:53-124`), нижче —
за яким призначенням їх застосовувати, а не просто перелік:

- `primary` — теракотовий, для CTA, активного стану навігації,
  індикатора прогресу (`Progress` вже це робить, `progress.tsx:48`).
- `success` — приглушений зелений, **тільки** для стану "виконано"
  (позначений пункт чеклиста), ніде більше.
- `destructive` — видалення власного пункту чеклиста, помилки форм.
- `secondary` / `accent` — теплі нейтральні поверхні: hover-стани,
  неактивні бейджі, другорядні кнопки. Не для акцентів вимоги уваги.
- `muted` / `muted-foreground` — фонові панелі, другорядний текст.
- `sidebar` / `sidebar-*` — власний, трохи інший відтінок фону саме
  для навігаційної панелі (App Shell, Задача 3) — не перевикористовувати
  поза сайдбаром, це навмисно виділяє навігацію з-поміж контенту.

## Патерни компонентів

**Пункт чеклиста** (типова структура для 7 розділів): `Checkbox` +
назва (`text-sm`) + опціональна ціна (`text-sm text-muted-foreground`,
вирівняна праворуч) + `Button variant="ghost" size="icon-sm"` для
видалення власного пункту (тільки коли `is_seed = false`, спец §2).

**Прогрес** (дашборд, Задача 4): `Progress` з `ProgressLabel` +
`ProgressValue` для підпису й числа поруч з треком — не окремий
текстовий блок збоку, компонент вже підтримує обидва слоти
(`progress.tsx:54-75`).

**Картка "фокус тижня"** (дашборд, Задача 4): `Card` з `CardHeader` /
`CardTitle` (номер тижня) / `CardContent` (`tip`-текст, `text-sm`).

**Пункт навігації** (App Shell, Задача 3): іконка з `@hugeicons/core-free-icons`
+ підпис, активний стан підсвічується через `primary`/`sidebar-primary`,
не через зміну розміру чи ваги шрифту.
