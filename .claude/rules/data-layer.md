# Data Layer

Компоненти ніколи не звертаються до сховища напряму. Тільки через
інтерфейс репозиторію в src/lib/repositories/.

## Контракт

- Один інтерфейс на сутність: ItemsRepository, HouseholdRepository,
  BudgetRepository, PregnancyRepository.
- Інтерфейс описує ЩО можна зробити з даними, і нічого не знає про
  те, ДЕ вони лежать. Жодних згадок localStorage чи Supabase
  у типах, іменах методів чи сигнатурах.
- Реалізацій дві: local (фаза 1) і supabase (фаза 2).
  Перемикання — в одному місці, не в компонентах.

## Async — обов'язково

Всі методи репозиторію повертають Promise, включно з локальною
реалізацією, де це технічно зайве.

Причина: localStorage синхронний, Supabase — ні. Компонент,
написаний проти синхронного доступу, не має loading і error шляхів,
і на фазі 2 його доведеться переписувати. Штучний async зараз —
це те, що робить фазу 2 підміною реалізації, а не переписуванням UI.

Кожен компонент, що читає дані, має явні стани: loading, error,
empty, дані.

## Заборонено

- localStorage / sessionStorage у компонентах
- import конкретної реалізації репозиторію в компоненті
- синхронні гетери даних
- дублювання типів сутностей: тип живе в одному місці,
  реалізації його імпортують
